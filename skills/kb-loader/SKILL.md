# 知识库规范解析器（kb-loader）

**定位**：插件与工程知识库（KB）绑定的唯一解析入口。规范正文的唯一事实源在 KB 内；本 Skill 只做「**定位 → 解析 → 出加载清单**」，不搬运、不复制任何规则正文。

**单一事实源**：KB 注册表与路由表（`index.md`「任务路由」、`projects/index.md`）为准。若本 Skill 所述与 KB 冲突，以 KB 为准并反馈修正本 Skill。

## 何时必须先加载本 Skill（MUST）

将在项目代码上执行以下任一动作**之前**：

- 写代码 / 新增或修改接口与字段（编码前）
- 审查代码 / `git diff` / 指定模块（审查前置）
- 生成 DDL / Entity / Mapper / 枚举（生成前）
- 修复缺陷（若涉及上述任一动作，修复前）

## 输入

| 输入 | 必填 | 说明 |
| --- | --- | --- |
| 任务类型 | 必 | 对齐 KB 根 `index.md`「任务路由」表的类别（数据库变更、后端业务开发、列表查询分页、代码审查…）；不确定时给一句话任务描述，由解析器归类 |
| 项目标识 | 选 | 调用方已明确时可直传；缺省则由本 Skill 解析 |

## 解析流程

### 0. 解析 KB 根（唯一配置点，禁止再散落硬编码）

1. 若当前上下文已含用户级 `~/.claude/CLAUDE.md` 声明的知识库根（形式：`Claude Code 全局指导。知识库根：<path>`），直接采用；
2. 否则 `Read ~/.claude/CLAUDE.md`，定位「知识库根：」声明，取其 `<path>`；
3. 仍不可得 → 询问用户。

记为 `$KB`。**调用方一律不得在其他位置硬编码 `$KB` 的绝对路径**，换机器 / 换路径只改 `~/.claude/CLAUDE.md` 一处。

### 1. 解析项目标识

1. `Read $KB/projects/index.md` 项目注册表；
2. 用当前工作目录（目标代码仓库根）匹配注册表「代码目录」列，取路径范围**最具体**的匹配项 → 得项目标识；
3. 未命中 → 用调用方显式指定的标识；再无 → 进入「无项目上下文」分支。

### 2. 解析任务路由

- **有项目**：`Read $KB/projects/<项目标识>/index.md`，按其「任务路由」表，收集本任务命中的文档清单；再按需补 `$KB/common/*` 通用补充（如涉及数据库补 `common/database/index.md`）。
- **无项目上下文**：`Read $KB/index.md`「任务路由」表，取其通用分支（多为 `common/*`、`backend/*`、`frontend/*`），并在清单头部标注「**未登记项目，仅加载通用规范**」；不臆造项目专属规范。

### 3. 输出有序加载清单

返回清单而非正文，形如：文档路径 + 一句话用途 + 建议顺序（index → 路由 → 命中文档 → 引用子文档）。由调用方按清单渐进 `Read`。

## 输出格式

```markdown
KB 根：<path>
项目：<id | 未登记>
任务类型：<类别>
加载清单（按序）：
1. <path> —— <用途>
2. ...
```

## 纪律

- **单一事实源**：只做路由解析；命中「需要把某规范正文写进插件」时，拒绝并回指 KB 对应文档。
- **上下文克制**：只加载命中文档，禁止把整个 KB 目录 Read 一遍；粒度以命中任务所需为界。
- **优先级**：安全与合规 > 模块/项目规则 > 技术栈与通用 > 个人偏好；项目级与通用级冲突时项目级优先。
- **未建档项目**：以通用规范为准，并提示可走 `projects/_template` 建档登记代码目录，之后即可被自动解析。

## 关联

- KB 权威入口：`index.md`（任务路由）、`projects/index.md`（注册表）、`projects/<项目标识>/index.md`（项目任务路由）
- KB 根声明位置：`~/.claude/CLAUDE.md`（唯一配置点）
